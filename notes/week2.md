# 2주차 학습 노트

## Day1. PRD 작성

### PRD 작성 흐름
- 문제 정의 → 대상 사용자 → 핵심 기능(MVP) → 범위 밖 → 기술 스택 → 완료 기준
- '왜 만드는가'를 먼저 정해야 기능을 덜어낼 기준이 생긴다

### 주제 선정 과정
- 처음 아이디어: 채용 사이트 공고를 모아 분야 비율·자격 요건·우대 사항을 보여 주는 대시보드
- 막힌 점
  - 링크드인·잡코리아 등은 크롤링을 약관으로 금지, 공개 API도 없음
  - 고용24·사람인 API는 있지만 자격 요건·우대 사항 본문 제공 여부가 불확실
  - 브라우저에서 API를 바로 부르면 키가 노출됨 → 서버(또는 서버리스)가 필요
- 결론: 2주차 목표는 "PRD → 앱 완성" 한 바퀴 경험이므로 외부 의존 없는 주제로 축소
- 데이터 출처가 기술 스택과 일정을 결정한다 → PRD에서 가장 먼저 확인할 것

### 최종 주제: 지원 현황 트래커
- 기능: 지원 추가(메모 포함) · 상태 변경 · 사용자 상태 추가 · Chart.js 현황 요약
- 저장: `localStorage` (서버·DB 없이 새로고침 후에도 유지)
- 범위 밖: 로그인, 동기화, 알림, 공고 자동 수집
- 향후 확장: Spring Boot REST API + DB로 저장소 교체
- 문서: `projects/02-main-app/PRD.md`

### 배운 점
- MVP는 "할 것"보다 "하지 않을 것"을 적는 게 더 중요하다
- 모호한 결정(데이터 필드 존재 여부 등)은 PRD의 '열린 질문'으로 남겨 두고 진행한다

## Day2. 플랜 모드로 트래커 MVP 구현

### 플랜 모드
- PRD → 플랜 모드에서 파일 구성·데이터 모델·구현 순서를 먼저 합의 → 승인 후 코드 작성
- 코드를 쓰기 전에 "하지 않을 것"까지 정해 두면 범위가 늘어나지 않는다

### 구현 포인트 (`projects/02-main-app`)
- 저장소 경계: localStorage는 `load()`/`save()`에서만 다룸 → 나중에 이 둘만 `fetch`로 바꾸면 Spring Boot API로 교체 가능
- Chart.js는 처음 한 번만 `new Chart()`로 만들고, 이후엔 `chart.data` 교체 + `update()` (다시 만들면 캔버스 재사용 오류)
- 사용자 입력은 `esc()`로 이스케이프한 뒤 innerHTML에 넣음, 링크는 `http(s)`만 허용 (`type="url"`은 `javascript:`도 통과시킴)
- `valueAsDate`는 UTC 기준 → 한국 오전 9시 전엔 어제 날짜가 됨, 로컬 날짜를 직접 넣음
- CDN 스크립트에 `integrity`(SRI) 해시를 달아 CDN이 변조돼도 실행되지 않게 함

### 작성 중 나온 오류
- 작은따옴표 문자열 안에 `'...'`를 넣어 스크립트 전체가 멈춤 → 문자열 안 따옴표 종류를 확인할 것
- CSS Grid의 `1fr`은 내용의 최소 폭 아래로 줄지 않음 → 모바일에서 넘침, `minmax(0, 1fr)`로 해결
